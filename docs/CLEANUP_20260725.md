## 2. 未删除的部分及原因

| 项 | 原因 |
| --- | --- |
| `admin/sdk/*`（49M） | **全部有活引用**。`aws` 用于 MinIO/S3 上传（`common.php`、`functions.php`）、`PHPExcel`/`phpoffice` 用于后台导出、各支付 SDK 在用。删除会导致 fatal error |
| `admin/app/home`、`portal`、`user`、`wxshare` | `home` 是 `default_app`（承载 `/`）；`portal` 承载《服务协议》《隐私政策》页面（登录弹窗引用）；`user` 含 S3 上传控制器 |
| `Video`/`Live`/`User` 中未被调用的方法 | 方法级删除风险高（内部交叉调用多），本轮只做模块级清理 |

## 3. 删表引发的代码适配（重要）

删表后有几处**仍在运行的代码**会访问已删表，已同步处理：

| 位置 | 处理 |
| --- | --- |
| `functions.php: getUserVip()` | 改为直接返回 `{type:'0', endtime:''}`，保留字段形状兼容客户端 |
| `functions.php: getUserLiang()` | 改为直接返回 `{name:'0'}` |
| `functions.php: checkUserFamily()` | 恒返回 `0` |
| `Api/Home.php` | 移除 `Domain\Guide` 依赖，`info.guide` 返回空数组 |
| `Api/User.php: getBaseInfo()` | 移除指向已删页面的菜单项（等级/装备中心/家族中心/青少年模式） |

**配置开关（关键）**：`cmf_option.configpri` 中以下开关原为 `1`，会让送礼分成走家族逻辑并致命报错，已置 `0`：

```
family_switch=0  family_member_divide_switch=0  turntable_switch=0
game_switch=''   game_xqtb_switch=0             game_xydzp_switch=0
```

`jackpot` 开关本就是 `0`，奖池代码不会执行。

**充值赠礼**：`cmf_charge_rules` 中 1 条规则带 `giftid=21`，该功能依赖已删的背包表，已置 `giftid=0, gift_num=0`。
